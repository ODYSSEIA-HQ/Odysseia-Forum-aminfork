# 子卡初始化状态修复

## 故障与代码修复

创建子卡时，Forum 将 `thread.initializing` 设为真，并在处罚任务完成后排入 `release-child:<数据库帖子ID>` 任务，撤销 Fluxer 的 `forum_initializing` 来源锁。旧版本未在成功结果中清除本地初始化标志，因此已完成任务的子卡被列表过滤。

修复仅在对应开放任务成功后，在任务完成的同一事务中清除该字段。它核对作品、Fluxer 平台、社区、原生帖子 ID、子帖角色和去重键，不更改其他锁、归档、删除、处罚或列表权限过滤。普通事件不能提前开放子卡。旧租约执行者仍受原有状态与尝试次数检查约束。

## 历史记录只读审计

1. 使用已授权的只读数据库连接运行同目录 `child_initialization_audit.sql`。保存记录 ID、任务 ID、状态、作用域是否匹配和未完成依赖数量。查询不读取正文或凭据。
2. 只将 `release_status=done`、`scope_matches=true`、`incomplete_dependencies=0` 的未删除子帖纳入进一步核验；缺失、失败、未完成、不匹配、已删除记录均不自动处理。额外核对创建任务及所属作品状态。
3. 在 Fluxer 的已授权只读接口或存储中按明确原生帖子 ID 核验社区与父论坛，以及 `thread_external_policies` 中该帖、`user_id=0`、`source=forum_initializing` 的策略。须确认 `kind=lock`、`active=false`，版本对应已完成开放任务。不能仅凭聚合 `locked=false` 判定，其他来源的锁可能仍有效。
4. 将两边证据、精确 ID 清单和预期行数交由操作者确认。当前交付没有数据修改脚本，也没有执行现场回填。

## 经单独确认后的恢复原则

暂停与清单有关的竞态写入，或在事务中按作品和线程加锁后重新核验条件。仅将已确认清单的本地 `initializing` 改为假，记录变更前后值及准确行数；条件变化或行数不符即回滚。不得重新创建帖子、重跑创建任务、解除其他处罚、恢复已删除内容，或批量开放所有初始化中的子卡。原生证据不一致时保持关闭并调查。

部署代码不会重跑历史已完成任务，重启也不能修复历史标志。代码更新只涉及 Forum，无数据库结构变更；历史修复须另行确认。发布后应先核对新子卡的创建、依赖、开放任务与列表状态，再处理已确认的旧记录。
